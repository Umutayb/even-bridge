# lets-code engine + Overseer + Even AI agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Durable sessions in even-bridge can run on lets-code (an owned `lets-code --mode rpc` child: mandate `ask`, subagents, experts, sandbox, factory on request) with restart-safe records, and one Durable overseer (the root conversation, `dur-overseer`) can list and read every session and propose start/message/interrupt/stop actions that run only after a confirmation outside the model, reachable from Even AI through the shim. Even AI itself can run as one persistent lets-code session (`dur-assistant`, profile `assistant`) whose tools live in the shim, behind the `evenai_engine` setting (default `loop`).

**Amended 2026-11-03** with the Task 1 spike results (`docs/overseer-spike.md`, commit 85a7040 on `feat/overseer`) and the Even-AI-agent design (`docs/superpowers/specs/2026-11-03-evenai-agent-design.md`, tasks A0–A7). Task order: 1, A0, 2, A1, A2, 3, 4, 5, A3, A4, A5, A6, 6, 7, A7.

**Architecture:** Hybrid B of the spec. Each Durable session row gets `engine: native|lets-code`. A lets-code session is a Durable conversation used only as a record (`even.lc-session` doc + `lc.*` write entries) plus one background task `even.lc-run` per busy period that drives a `PiSession`/`PiRpcClient` child inside a `systemd-run --user --scope` unit `even-lc-<sid>`; a restart reruns the task, which re-spawns the child with `--session <file>` and sends one "you were cut off" prompt (or `/factory resume <id>`). The overseer is `harness.root()` with an in-process `even-overseer` extension (no CodingTools); gated tools only write pending actions whose summaries are built by host code, and `POST /api/overseer/actions/:id/confirm` (shim spoken/HUD yes, or the phone's `permission_request` on `dur-overseer`) executes them. The Even AI agent is a second `LetsCodeEngine` profile: one always-warm child `dur-assistant` without shell or file tools (`-ne -e <lets-code ext> -e even-assistant.ts --tools …`), whose tools are HTTP calls from the pi extension `even-assistant.ts` to a token-checked tool server in the shim (`127.0.0.1:8814`) that acts on the open Even AI turn's WebSocket; the shim relays each glasses turn (`POST /api/assistant/prompt` + SSE) and owns the progress lines, HUD chunking and the pre-turn yes/no gate.

**Tech Stack:** Node 24 ESM, `@earendil-works/pi-durable@1.5.0` (pinned, unchanged), node:test, pi 1.0.3 + lets-code `d20144e` via `~/.local/bin/lets-code` (the live bridge's bin; `pi-inference` only `exec`s it); Python 3 / FastAPI / SQLite / pytest in the shim.

**Specs:** `docs/superpowers/specs/2026-11-03-overseer-design.md` (copy of `borealis:~/tasks/overseer-design.md`; the user's answers to its §4 are binding) and `docs/superpowers/specs/2026-11-03-evenai-agent-design.md` (its **Decisions** are binding; its open questions §13 get the defaults in **Rulings A**, each marked *default pending user*). Spike results: `docs/overseer-spike.md` (Task 1) and `docs/assistant-spike.md` (Task A0).

## Rulings (decisions this plan makes where the spec leaves a choice)

1. **One task per busy period.** The record is a conversation doc `even.lc-session`; a background task `even.lc-run` exists only while the child works. Idle sessions hold no process and no task, so bridge restarts while idle never count against `restartLimit`. The child stays up `LC_IDLE_KEEP_MS = 120000` after a run, then stops; the next prompt re-spawns it with `--session <file>`. A child with an open dialog (a held factory checkpoint, a pending mandate ask) is not idle and is never idle-stopped.
2. **Own session dir.** Children run with `--session-dir <dir of storePath>/lc-sessions/<sid>` (flat layout, spike: `<dir>/<ISO-ts>_<uuid>.jsonl`, written lazily at the first prompt; `get_state` returns `sessionFile` at once), so the pi provider (which scans `~/.pi/agent/sessions`) never lists or probes them; the child's pi session id is still claimed for `durable`. Subagent sessions land in `~/.pi/agent/lets-code-runs/<pi session id>/`, which nothing of ours scans; `forgetSession` removes that dir. The spec's "a terminal drives the file → only watch" check is not built: nothing else opens files under `~/.even-terminal` (the guard denies it to agents). `findExternalPi` additionally skips any process whose `/proc/<pid>/cgroup` names an `even-lc-` scope — this holds only because the child env sets `LETS_CODE_MEM_WATCH=false LETS_CODE_MEM_GUARD=false` (spike Finding 2).
3. **Scope cleanup by own sids**, not by glob: startup and shutdown stop `even-lc-<sid>.scope` only for lets-code rows of this store (a throwaway instance never kills the live bridge's children). Same env precondition as ruling 2.
4. **Factory toggle** = `/mode orchestration` (on) and `/mode ask` (off), re-sent right after every spawn. `get_state` has no mode field, so the engine tracks the mode from the `notify` text (`mode: orchestration` / `mode: ask`) and `setFactory` resolves only on that notify (5 s, else 504 `lets-code did not confirm the mode`); the record keeps the wanted `factory` and the seen `mode`. With a ticket text the bridge writes `<cwd>/.factory/ticket-<epochMs>.md` and sends `/factory start .factory/ticket-<epochMs>.md[ <howToRun>]` — the how-to-run words go **unquoted** (one line, no quotes; lets-code splits on whitespace). **Experts are host-global** (`~/.pi/agent/lets-code-state.json`): the bridge never sends `/experts enable`; the operator enables the factory's five experts once (Task 7), and `LETS_CODE_EXPERTS_ON` is not set.
5. **Glasses cannot edit text:** `editor` dialogs are answered `cancelled`, and an `Edit` option is removed from select dialogs before they reach the glasses. No `Cancel` option is added to a factory checkpoint (cancel = stop the run; `Stop` is already offered).
6. **`dur-overseer`** is a virtual session row mapped to `ROOT_CONVERSATION_ID`; it is listed first, chat-able from the phone Terminal, and cannot be stopped or archived (403).
7. **Late answers** of `overseer_ask` are reconciled from a doc of pending asks (`even.overseer.asks`) on every outbox read and at startup, so an answer reaches the outbox exactly once, also across restarts.
8. **Limits for overseer starts live in the bridge** (2 non-archived agents of origin `evenai|overseer`); the shim reaper **adopts** an `origin: overseer` agent without a registry row (TTL from the agent's `ttlS`, ≤ 43200) instead of stray-stopping it, because a phone confirmation bypasses the shim.
9. **Shim engine default comes from the bridge:** `GET /api/agents` advertises `engines`; `dispatch_agent` defaults to `lets-code` when advertised, else `native`. No extra shim flag.
10. **`agent_factory(label, on)`** is a gated voice tool (staged, spoken yes), like `message_agent`.
11. **One gate (Q9):** with `SHIM_OVERSEER_ENABLE=1`, the shim's confirmed `dispatch_agent`/`message_agent` execute through `POST /api/overseer/actions` + `/confirm` (one audit trail, one limit check); staging and the spoken yes stay in the shim.
12. **Standing orders** (Task 6) are exact-match orders `{sid, text, maxTimes ≤ 3, until ≤ now+12 h}`: a later `session_message` with the same sid and text runs without a new confirmation while the order has uses left.
13. **Ideate hand-off** steps run only when the shim has the Ideate MVP (`shim/ideate.py`); otherwise Task 6 ships check-ins, nightly reset and standing orders, and the Ideate steps stay open.
14. **Memory cap only where it exists (spike).** `lcMemoryControllerAvailable()` reads `/sys/fs/cgroup/cgroup.controllers` once at start; `memoryMax` goes into the scope only when it lists `memory`. Without it the engine logs `lets-code: no memory cgroup controller; MemoryMax not applied (operator: add cgroup_enable=memory to /boot/firmware/cmdline.txt and reboot)` once and the banner says `nomem`. Nothing reads `MemoryCurrent` (it is `[not set]` without the controller).
15. **`LC_MAX_LIVE` defaults to 1** (2 × 322 + 600 = 1244 MB was marginal against 1293 MB available with swap full, and the assistant adds ~150 MB warm); raising it to 2 is an operator env change after measurement (Task 7).
16. **Bin and model prefix.** The engine's default bin is the live one, `lets-code`. `isLetsCode(bin)` (pi provider) matches the basename `lets-code` **or** `pi-inference`, so `launcherModel()` strips the `lets-code/` prefix for either.
17. **Mandate asks reach the user as yes/no.** `dialogKind` maps `MANDATE_TITLE = /^mandate \(ask\): /` to `"confirm"`; the phone's `permission_request` and the glasses offer `Yes` → `Allow once` and `No` → `Deny`. `Allow for this session` is never offered remotely (each risky step is confirmed on its own). Tests and smoke runs trigger an ask with a write **outside** the project (a write inside cwd asks nothing).
18. **Factory hold, interrupt and resume.** A checkpoint is held by leaving it open (no sweep, no idle stop, survives watchers leaving). An interrupt while a checkpoint is open stops the factory run (lets-code semantics) and the engine says so with the frame `{type:"error", message:"factory run <id> stopped at the <checkpoint> checkpoint; /factory resume <id> continues it"}`. After a bridge restart `findFactoryRun` resumes only ledgers with status `running|waiting`; a `stopped` run is resumed only when the user asks.
19. **The factory worktree is allowed, narrowly.** `even-guard.ts` treats `~/.pi/agent/lets-code-factory/<id>/work` as inside the project only when that run's ledger `repo` equals or is under `EVEN_GUARD_CWD`; the rest of `~/.pi/agent/` stays denied. The empty first commit intake adds to the cwd repo is accepted (it is inside the sandbox). `stopSession` leaves the factory dir to lets-code.
20. **Crash leftovers (spike Finding 9).** After a SIGKILL the session file can end with an assistant `toolCall` without a `toolResult`, and `~/.pi/agent/lets-code-sessions/<pid>.json` stays behind. `readHistoryFile` tolerates the dangling call; `LC_CUTOFF_PROMPT` tells the model its last tool call may have no result; before the respawn the engine deletes `lets-code-sessions/<record.childPid>.json` when that pid is no longer alive. If the recorded session file does not exist yet (killed before the first prompt), the respawn starts without `--session` and records the new file.
21. **Tokens.** The lets-code engine and the assistant strip `LETS_CODE_TOKEN` (and every `*_TOKEN`/`*_KEY`) from their children; the assistant's tool-server token goes in as a file path. The native pi provider's children (live bin `lets-code`, which today inherit `LETS_CODE_TOKEN` from the unit env) are left as they are in this plan, because flag-off behavior must stay identical; removing `LETS_CODE_TOKEN` from the bridge unit is an operator follow-up after checking `~/.config/lets-code/config` (Task 7).
22. **Scratch on disk** (see Global Constraints): `/tmp/ovs-*` from the earlier plan text is `~/tmp/ovs-*` everywhere.

### Rulings A — the Even AI agent (design §12/§13)

23. **Assistant profile, not an agent.** `dur-assistant` runs on `LetsCodeEngine` with profile `assistant`: no mandate, sandbox, subagents or guard extension (it has no shell/file tools), `-ne` plus explicit `-e` (global extensions `grocerybot-confirm.ts`, `max-images.ts` stay out), always warm (spawned at bridge start, respawned with `--session` on exit, backoff 2 s → 60 s), own slot (not in `/api/agents`, `liveCount`, reaper or TTL), no resume after a restart (a note "(bridge restarted; your last answer was lost)" and the shim says "I lost that one, please ask again."), dialogs never to the phone (frames `assistant_dialog`).
24. **Notes without a run.** Host notes (restart, pre-turn results, farewell, fast path, hand-off summary) reach the model through the extension command `/even-note <file>` (the bridge writes `<store>/lc-sessions/dur-assistant-notes/<ms>.txt`, 0600; the extension reads, deletes and `sendMessage`s it with `triggerTurn: false`). Notes sent while a run is busy are queued and sent after `agent_end`.
25. **One schema source.** The tool list and descriptions come from the shim (`GET /tools/schema`); the extension caches the last good schema at `<store>/lc-sessions/assistant-tools-schema.json` and uses it when the shim is down at child start. Zero tools (no live schema, no cache) → `POST /api/assistant/prompt` answers 503 `assistant tools not loaded` and the shim falls back to the loop for that turn.
26. **Read tools come to the assistant directly (Q2, default pending user).** The assistant gets `sessions_list`, `session_read` and `overseer_outbox` (read-only, untrusted) through bridge routes backed by the Task 4 host; it does **not** get `overseer_ask`. The overseer stays for check-ins and the outbox. The host is built when either the overseer or the assistant is enabled.
27. **Q1 (default pending user):** if A0 measures the medium-thinking no-tool final answer at p50 > 8 s, turns whose text has no tool hint (`NO_TOOL_HINT`: no calendar/notes/list/app/agent/web/KB word) run at `low`, all others at `medium`; otherwise every turn is `medium`. The shim switches with `POST /api/assistant/model {thinking}` before the prompt, only when it differs.
28. **Q3 (default pending user):** daily reset at 04:00 local when idle (busy → retry in 10 min): `compact` with "Keep open questions, pending tasks and the user's stated plans.", `new_session`, the summary as the first note. Core memory and that summary survive; nothing else.
29. **Q4 (default pending user):** the phone's KB "Ask about this" stays on the shim loop.
30. **Q5 (default pending user):** memory writes only on request: `memory` `remember`/`forget` is blocked unless the user's text in this run matches the shim's `_REMEMBER_RE` (sent in the schema as `rememberPattern`), with or without untrusted results in the run.
31. **Q6 (default pending user):** `dur-assistant` is listed read-only in the phone Terminal as "Even AI" (history and watch work; prompt/stop/forget → 403 `Even AI is read-only here`).
32. **Q7 (default pending user):** switching to a Claude model first hands off (the same compact → new session → summary note as the daily reset), so Claude starts from the summary only; switching back to qwen keeps going in that new session (the earlier transcript stays readable in its own file).
33. **Q8 (default pending user):** cutover = 7 green nightly runs plus 3 days of the user's own use with zero backstop triggers; retirement of the loop needs that plus 14 nightly runs with zero backstop triggers.
34. **Q9 (default pending user):** the spoken yes confirms agent actions until the HUD `confirm:true` frames are recorded (Task 1 Step 6); then the HUD dialog is used behind `SHIM_AGENT_HUD_CONFIRM=1`.
35. **Q10 (default pending user):** bare feature names (`bare_app_token`) keep the no-model fast path: `cmd` directly, then a note to the assistant.
36. **Memory import timing.** The one-time import runs while `EVEN_BRIDGE_ASSISTANT_ENABLE` is off (no child holds the store). kv `ai_memory` stays writable during the shadow period; the import is idempotent and re-runs at cutover, after which kv `ai_memory` is frozen (`kv ai_memory_frozen=1`). KB pointers go through the bridge (`PUT /api/assistant/memory/pointers`), applied when idle.
37. **Glasses probes ride on A4.** The app-behaviour checks of design §0.6 (progress text + pause + answer, a 30 s gap after `start`, a `request` during an open turn, `ask` after `end`) need a shim that sends those frames; A4 ships them as probe phrases behind `SHIM_ASSISTANT_PROBE=1`, and the operator runs them in A7 Step 2. Until then A4 assumes the progress line is appended, not replaced.

## Review Focus

1. A prompt for a lets-code session whose child has exited (idle grace over, or it crashed between runs) must re-spawn with `--session <file>` and deliver the prompt exactly once, also when the session file ends with a tool call that has no result — Task 2 tests `prompt after the child exited respawns with --session and sends once`, `restart mid-turn re-spawns with --session and sends the cut-off prompt once`.
